# side-inbox

[English](README.md) · **中文** · [排查问题](docs/troubleshooting.zh-CN.md)

**旁边聊出的好东西，先存下来，需要时再带回工作。**

macOS 本地文本收件箱，供 Claude Code、Codex 和其他应用之间收集、取用内容。MIT 开源。

## 问题：追问有了成果，但现在还不想打断主任务

主对话正在做事，你选中回答中的一段，在 Side Chat 里继续追问。几轮之后，你整理出一个方案、一段修改意见，甚至一份长文档。

这时你想做的是：**把这段成果留下，继续当前工作，等需要时再用。**

直接粘回主对话，会多出一轮消息，把暂时用不上的内容带进来；留在原窗口，又要记得去哪里找、复制哪一段。跨到 Quick Chat、网页或另一家 AI 工具后，这个过程更零散。

side-inbox 把“保存”和“使用”分开，让你自己决定什么时候把内容带进工作的对话。

## 解法：复制 → 存到收件箱 → 需要时再读

```mermaid
flowchart LR
    A[Side Chat / Quick Chat / 网页里的文字] -->|选中并复制| B[按保存快捷键]
    B --> C[本机收件箱 ~/inbox]
    C -->|以后通过 merge 选择| D[读取 / 归档 / 删除 / 保留]
```

1. **收集时：**选中文字，复制，按你设置的快捷键。文字保存为本机文件，不给主对话发送消息。
2. **继续工作：**留在侧边继续聊，或回到主任务。此时不用调用 `merge`。
3. **需要时：**在 Claude Code 或 Codex 中列出收件箱，再指定要读哪一条、怎么用。

例如：主对话在写代码，你在 Side Chat 里聊出了新的测试方案。先存起来，等代码完成，再说：“读收件箱里的测试方案，按它检查这次修改。”

**保存的只是你复制的文字。** 不自动保存整段会话、未复制的历史、模型设置或对话之间的关系。

## 安装（macOS）

需要 Git、macOS「快捷指令」，以及生成快捷指令所需的 `/usr/bin/python3`。Claude Code、Codex 安装其一或两者均可；只收集文字时不需要运行 AI。

```bash
git clone https://github.com/zaozhiyi/side-inbox.git
```

```bash
cd side-inbox
```

```bash
./install.sh
```

脚本把命令装到 `~/.local/bin/side-inbox`，创建 `~/inbox`，并为检测到的 Claude Code、Codex 安装 `inbox` 和 `merge` 技能。

接着在弹出的「快捷指令」窗口中：

1. 点 **添加快捷指令**。
2. 打开它，在 **ⓘ → 添加键盘快捷键** 设置一组按键，例如 **⌃⌥I**（Control + Option + I）。
3. 在「快捷指令 → 设置 → 高级」开启 **允许运行脚本**。

**首次检查：**复制一段无敏感信息的测试文字，在常用应用中按快捷键，再到 Finder 的“前往文件夹”输入 `~/inbox`，确认文件出现。正常会显示保存通知，但没看到通知不等于没存成功。

`⌃` 是 Control，`⌥` 是 Option，`⌘` 是 Command。外接键盘的 Start／Windows、Alt 等键要以 Mac 实际识别的映射为准；示例按键并非强制。如果与 Typeless 等工具冲突，可另选一组，如 `⌘⇧9`（Command + Shift + 9），并检查是否已被占用。

**快捷指令的键盘快捷键可能无法在某些应用中触发。** 此时先在「快捷指令」里点击运行，确认保存功能正常，再按[排查指引](docs/troubleshooting.zh-CN.md)处理。当前公开安装流程使用 macOS 快捷指令，不保证每个应用都能接收快捷键。

## 日常怎么用

| 你想做什么 | 操作 | 当前对话会看到什么 |
|---|---|---|
| 保存文字，继续手头的事 | 复制 → 保存快捷键 | 不发送消息 |
| 看有哪些内容 | Claude Code：`/merge`；Codex：`$merge`；或说“收件箱里有什么” | 文件名、行数和首行摘要 |
| 使用其中一条 | “读收件箱 2 号，按它修改方案” | 所选文件全文 |
| 只归档到项目 | “把 2 号移到 notes/方案.md，不要读取正文” | 移动结果 |
| 暂时不处理 | “都留着” | 文件继续保留 |
| 删除一条 | “3 号不要了” | 删除结果 |

编号以**最近一次列表**为准，文件增删后可能变化；也可以指定文件名。`merge` 不会自动读完全部内容，也不会自动合并进主对话或代码。

`inbox` 命令仍然存在：Claude Code 用 `/inbox`，Codex 用 `$inbox`。它是可选的“先看少量预览，再确认保存”入口，会在当前对话增加消息和预览。**想完全绕过主对话保存时，用快捷键。**

取用需要技能已安装，且当前 agent 有权限读取这台 Mac 的文件。网页聊天、远程或云端会话不会因为安装了本机工具就自动获得收件箱访问能力。

## 收件箱和项目是什么关系？

默认收件箱是你 Mac 用户目录下的 **`~/inbox` 文件夹**，独立于任何项目和对话。同一用户下的 Claude Code、Codex 共用它。

```text
~/inbox/
  2026-10-02-100000-测试方案.md
  2026-10-02-110000-接口设计.md

某个项目/notes/方案.md   ← 需要归档时，再把选中的文件移到这里
```

每次成功保存都会留下一个文本文件；内容重复时可能跳过。后续复制不会替换已经保存的文件，关闭聊天也不会删除它们。读取不会移走文件，归档会移动文件，删除需要你明确指定。没有自动过期或强制清空。

## Codex 的 Side Chat、Quick Chat 都能这样用吗？

可以把它们当作文字来源。即使你从主对话打开 Side Chat，又打开 Quick Chat，收集动作仍然相同：**选中需要的部分 → 复制 → 按保存快捷键。** 快捷键是否能在当前应用触发，需要按下方指引检查。

这里有两点区别：

- **窗口看起来层层展开，不代表它们是同一种“父子对话”。** Quick Chat 是普通 ChatGPT 聊天入口；不要据此推断它继承了 Side Chat 的完整上下文或模型。[官方说明](https://learn.chatgpt.com/docs/projects)
- **原生回流与收件箱可以并用。** 若界面提供“添加到 Codex”，可以直接使用。side-inbox 适合只保留选中的文字、稍后再处理，或交给另一项目、Claude Code 使用。

桌面端 Side Chat 与终端里的 `/side` 也不能混为一谈。官方文档将 Codex CLI 的 `/side` 描述为临时会话，并说明不能在其中再开 `/side`；这不能推导出所有桌面窗口都有同样限制。[CLI 文档](https://learn.chatgpt.com/docs/developer-commands)

本项目不依赖“Side Chat 必须只读”或“关掉必定丢失”这类前提。各产品的保存、权限和恢复行为可能随版本变化。以上产品说明核对于 **2026-10-02**。

## 数据与边界

- **本地收集，不调用模型。** 工具按需读取剪贴板文字，不持续记录每次复制；保存动作不把正文发给 AI。之后让 agent 读取时，正文才会进入该对话，按该产品的数据规则处理。
- **不改写文字。** 以 `.md` 文件保存剪贴板提供的纯文本；缺少末尾换行时会补一个。图片、附件和富文本样式不会一起保存，来源应用未复制出的 Markdown 格式也无法恢复。
- **减少重复，不保证复制正确。** 快速保存会检查剪贴板是否变化、收件箱是否已有相同文本。但复制到错误内容时，工具无法知道你的本意。看通知或文件确认，必要时删除。
- **收件箱是普通文件夹。** 不加密、不自动同步，也不是隔离其他有文件权限的程序的安全沙箱。文件名、通知、列表和本地 `.log` 可能包含内容标题。
